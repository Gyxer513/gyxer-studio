# Roadmap to 1.0

Цель: стабильная 1.0, пригодная как основной инструмент оптимизации разработки внутренних проектов.

## Статус после аудита 2026-07-20

Полный цикл проверен вручную: все 5 примеров (`examples/*.json`) проходят
generate → npm install → prisma generate → build → тесты. Сгенерированное
приложение (blog, sqlite) поднимается, Swagger отвечает, CRUD работает.
Editor, CLI (generate/validate/editor), MCP-сервер (14 tools) — рабочие.

## Блокеры 1.0

- [ ] **Опубликовать 0.6.0** — npm (сейчас опубликована 0.5.0, mcp — 0.6.0-alpha.1), Docker Hub, git push. Версии и changelog'и уже подготовлены локально.
- [ ] **`gyxer generate --force`** — при существующей выходной папке CLI задаёт интерактивный вопрос; в CI/скриптах это вечное зависание. Нужен флаг перезаписи и/или авто-детект неинтерактивного терминала.
- [ ] **Runtime-smoke в CI** — юнит-тесты не поймали ни бага DTO (required+default), ни sqlite-пути вне docker-тома; поймал только реальный запуск. Нужен CI-job: generate (sqlite) → build → boot → curl CRUD.

## Важное до 1.0

- [ ] **Smoke всех модулей** — runtime проверен только базовый CRUD. file-storage / queues / search / cache / websockets / auth-* нужно поднимать хотя бы раз через docker-compose (Redis, MinIO, MeiliSearch) и дёргать healthcheck.
- [ ] **Сборка сгенерированной админки** — `admin/` SPA генерируется, но её `npm install && build` в E2E не входит.
- [ ] **MySQL-путь** — заявлен в схеме, но нет ни одного примера и ни одного прогона. Либо протестировать, либо честно убрать из 1.0.
- [ ] **Обновить vitepress до 2.x** — закроет 2 оставшиеся уязвимости dev-цепочки (vite path traversal).

## Косметика / после 1.0

- [ ] Code-splitting редактора (чанк 525 kB, React Flow).
- [ ] Почистить мёртвые ветки на origin (~11 штук, локально уже удалены).
- [ ] `configs/` из редактора: кнопка Generate пишет конфиг молча в `./configs/` — стоит показывать путь в UI.
